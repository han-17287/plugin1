# 파란 플러그 · 양손 모션과 발광 작업서

Unity 6000.6.7f1의 `Assets/Scenes/Main.unity`에서 **파란 플러그 시험 · 빨래골목**을 연다. 정비소와 교정대에서 E로 기술을 익히고 같은 소켓을 겨눈다. 블레이드 미장착 상태에서 소켓을 겨누고 좌클릭을 누르면 오른손이 플러그를 돌린다. 놓으면 날아가 체결된다. C를 새로 누르면 옥상으로 견인하고, V를 새로 누르면 창문 아래로 스윙한다. 연결 직후 걷거나 점프해서 출발점을 바꿀 수 있다.

[양손 자세 여섯 컷](BluePlugPoses.png)은 게임 원화와 손 위치를 합성한 작업용 시트다. Unity Play Mode 캡처는 별도로 확인한다.

## V3 · 어느 손이 어느 줄을 잡는가

일반 플레이의 보행과 점프는 기존 백 경위 원화의 선과 발 피벗을 사용한다. 플러그를 돌리면 `BluePlugPoseAtlas`가 같은 인물의 모자·제복·부츠를 갖춘 110 PPU 몸 시트로 바꾸고, 양팔과 손을 관절 위치에 따로 그린다. 서 있는 자세와 착지는 부츠, 공중 견인과 스윙은 골반을 기준으로 회전한다. 왼손 감개와 오른손 그립은 같은 프레임의 손 소켓에서 전선과 만난다. 조커 최종 레이저 충돌 구간은 기존 원화와 동작을 사용한다.

| 단계 | 몸과 손 | 전선·입력 |
|---|---|---|
| 돌리기 | 왼손은 허리 앞 릴을 고정하고 오른손이 원을 그린다. 몸통이 궤도와 이동 속도에 맞춰 기울고 지상에서는 보폭 위상에 맞춰 다리 자세가 변한다. | 밝은 줄은 **왼손 → 오른손 → 플러그 뒤쪽 부싱**에 닿는다. 기본 4회전/초에서 완충하면 6.6회전/초다. |
| 던지기 | 실제 비행 첫 프레임에 오른손 손바닥이 열린다. 앞쪽으로 뻗은 팔이 0.18초에 걸쳐 돌아오고, 왼손 릴이 급하게 풀린다. | 오른손 매듭을 같은 프레임에 제거한다. 단자가 가까워 이미 체결됐어도 릴리즈의 마무리 자세를 보여 준다. |
| 연결 유지 | 양발·공격 자세는 기존 플레이어가 제어한다. 왼손에 남는 릴이 걸음에 따라 움직인다. | 왼손에서 콘센트까지 늘어진 선을 그린다. 물리 힘은 0이다. |
| 견인·스윙 | 견인에서는 왼손이 하중을 받아 몸이 뒤로 뻗는다. 스윙에서는 로프 방향과 호의 진행에 따라 무릎과 몸통을 접었다 편다. | 새 C/V 입력만 받는다. 견인 도착과 스윙 이탈 때 실제 선을 숨긴다. 복귀 자세의 기본 길이는 0.26초다. |
| 빗나감·회수 | 릴이 반대 방향으로 돌고 오른손이 왼손 쪽에서 줄을 정리한다. | 되감긴 후 선·헤드는 숨고 손의 재장전 표시만 짧게 남는다. |
| 모드 전환·중단 | 돌리는 도중 공격 모드로 바꾸면 준비 자세를 푼다. 체결 후 무기를 꺼내면 왼손의 남은 연결을 계속 표시한다. | 피격·재시도·방 이동에서는 세션과 그림을 함께 지워 이전 버튼과 선을 재사용하지 않는다. |

### 리깅과 뒤집기

`BluePlugCharacterMotion`은 캐릭터의 표시용 SpriteRenderer를 받아 양팔을 한 번 구성한다. 각 손 스프라이트 Transform이 실제 `LeftGripSocket`, `RightGripSocket`이다. `DefaultBluePlug.asset`의 **양손 모션 · 표시 전용**에서 `windGripRadius` 0.43타일, `reelScale` 0.82, `reelPayoutSpeed` 1200°/초, `reelReturnSpeed` 920°/초를 조절한다. 두 링크의 길이 0.29·0.30 유닛으로 팔꿈치를 구하고 손이 닿는 거리로 목표를 제한한다. 몸이 돌아서면 신체 좌표계에서 한 번만 X를 반사한다. 왼손과 오른손 이름은 백 경위의 신체를 기준으로 유지한다.

`BluePlugVisuals.DrawCable`은 19개 정점 중 회전할 때만 5번 정점을 오른손에 고정한다. 비행부터는 처음과 끝만 고정한다. 핀 끝 피벗에서 헤드 뒤쪽으로 55/52 유닛 떨어진 부싱이 전선의 종점이다. `orbitHeight` 기본값 0.73으로 준비 동작의 세로 폭을 줄이고, 궤도 앞·뒤에 따라 몸통과 플러그의 그리기 순서를 바꾼다. 벽 옆에서 이 시각 보정이 장애물을 넘으면 원래 검사된 팁 위치를 사용한다.

정해진 속도로만 재생하는 클립은 손그림의 아크·표정·의상을 프레임별로 다루기 좋다. 이 게임은 돌리는 동안 이동과 방향 전환이 가능하고 충전량에 따라 회전 속도도 연속으로 달라진다. 그래서 다리는 일반 보행과 같은 보폭 위상에서, 상체와 손은 실제 플러그 위상에서 읽는다. 실제 비행이 시작되는 프레임에 오른손을 펴고 약 0.055초 동안 투척 방향으로 뻗는다. 견인 끝에서 소켓이 손 뒤로 넘어가더라도 상체는 이동 속도를 따라가고 손만 접점 쪽으로 향한다. 이후 PSD 파트와 2D Animation 본으로 원화를 교체할 때도 손 소켓의 월드 좌표와 실제 Flying 진입 신호를 같은 이름으로 유지하면 전선과 소리를 재사용할 수 있다. 오토바이 탑승 중에는 별도로 그린 기존 라이더 자세와 전선 출발점을 사용한다.

**V3 확인.** 실행 중 **PLUGIN → P2 → 플러그 양손·전선 연출 검사**를 눌러 임시 캐릭터의 양쪽 손 소켓과 전선 정점을 대조한다. 이어 양쪽을 번갈아 보며 정지·달리기·점프 상태에서 짧게 탭하고 0.65초 홀드한다. 0.25배속으로 오른손이 열린 첫 비행 프레임에서 줄의 꺾임이 없어지는지, 왼손은 그대로 쥐는지 본다. 체결 후 좌우로 걷거나 점프해서 선이 왼손을 따라오는지, 도착 직후 선과 릴의 잔광이 구분되는지 확인한다. 자주 생기는 오류는 SpriteRenderer.flipX에 더해 자식 계층까지 음수 스케일로 뒤집는 경우, 캐릭터의 물리 중심을 줄 시작점으로 쓰는 경우, 손을 그리기 전에 전선을 먼저 갱신하는 경우다.

## V5 · 피복, 필라멘트, 궤적

이 브랜치의 패키지 목록에는 URP와 Shader Graph가 없다. 기본 렌더러에서도 몸통의 어두운 고무·유리·두 핀을 원화로 먼저 그리고, 같은 피벗의 필라멘트 마스크를 그 위에 가산한다. Main 카메라의 기존 `AncientCameraFX` 후처리는 고품질에서 작은 후광을 더한다. 순찰처럼 후처리 설정이 다른 카메라에서도 플러그 자체의 마스크와 국소 후광이 켜진다. URP 2D를 사용하는 체크아웃에서는 고품질일 때만 선택된 소켓·플러그에 점광원을 붙일 수 있다. 배경에 실제 빛을 받으려면 Renderer2D, 해당 Sorting Layer 및 Sprite-Lit 재질이 필요하다.

| 조절 위치 | 기본값과 의미 |
|---|---|
| 플레이어의 `BluePlugVisuals` | `plugScale` 1, `cableWidth` 0.037타일, `orbitHeight` 0.73, `peakEmission` 4, `lightRadius` 1.15타일. 투척·도착 판정은 별도로 관리한다. |
| 전선 중심·피복 | 몸통은 중심 폭의 2.15배인 어두운 피복, 후광은 폭 5배에 불투명도 0.16. 중심색은 sRGB `#5CCBFF`. 밝은 창문 앞에서는 피복과 금속 핀 사이의 음영 틈이 읽혀야 한다. |
| `BluePlugEmission.mat` | 공용 마스크·후광 기본 밝기 1.65. 헤드 필라멘트만 MaterialPropertyBlock으로 회전 0.5→4, 비행 3, 견인/스윙 3.4, 체결 안정 0.9, 회수 0.6을 준다. |
| 회전 궤적 | 14점으로 그린 두 겹의 부채꼴. 약한 회전은 짧고 성기게, 완충은 길고 밝게 이어진다. 회전 속도가 높은 화면에서도 현재 플러그가 궤적 끝에 남는다. |
| 비행 TrailRenderer | 부싱이 약 0.07타일 움직일 때 새 점을 찍는다. 충전에 따라 0.055→0.095초, 폭 0.075→0.14타일. 청색 끝이 투명해지며 더 가늘어진다. |
| 전류 이동 | 이동한 방향으로 짧은 신체 잔상을 남기고 양끝을 고정한 전선 중간에만 미세한 지그재그를 준다. URP의 추적 광원은 이동 중 손을 따라 경로를 훑는다. |
| `BluePlugSocket` | `panelScale` 1, `glowIntensity` 0.82. 조준·연결한 소켓 국소광 반경은 1.4 × 패널 크기다. 잠금과 차단은 문양으로도 읽는다. |
| `BluePlugTravelFX` | `afterimageInterval` 0.028초, `afterimageLife` 0.15초, `afterimageDistance` 0.12타일. 잔상 6칸과 스파크 16칸을 재사용한다. 체결 6개·도착 8개, 저자극에서는 각 2개. 회색 배경에 섞이면 불꽃 수보다 피복 대비와 접점 문양을 먼저 확인한다. |

### Shader Graph에서 같은 신호 만들기

URP 2D용 편집 가능한 [SignalCord](OptionalURP/BluePlugV5/Resources/BluePlugURP/SignalCord.shadergraph)와 [PlugFilament](OptionalURP/BluePlugV5/Resources/BluePlugURP/PlugFilament.shadergraph)도 동봉했다. 이미 URP와 Shader Graph가 설정된 프로젝트에서는 `OptionalURP/BluePlugV5` 폴더를 `Assets` 아래로 복사하고 **Tools → Blue Plug → Validate URP Graphs**로 임포트를 검사한다. 활성 URP에서 원본 리소스 경로의 그래프를 자동 선택한다. 카메라에 `BluePlugDockBloom`을 추가하면 체결 때만 기본 0.10초 동안 가중치 최고 0.30으로 짧게 빛난다. 일반 카메라에는 기존 후처리를 사용한다.

기본 렌더러에서 사용하는 두 셰이더의 실행 원본은 `Assets/Resources/Shaders/BluePlugCord.shader`와 `BluePlugEmission.shader`다. URP용 Sprite Unlit 그래프를 편집할 때 같은 셰이더 속성 이름을 쓰면 상태별 재질 블록 값을 그대로 받을 수 있다.

1. **전선.** UV0를 Split한다. U에 `Max(1, _CableLength) × 0.60`을 곱하고 `Time × 2.5 × _Flow`를 뺀다. Fraction → Subtract 0.5 → Absolute → Smoothstep(0.03, 0.18) → One Minus로 이동 펄스를 얻는다. 회수는 음의 Flow, 느슨한 연결은 0.23이다.
2. **가장자리.** V × 2 − 1에 진폭 0.065 이내의 떨림을 더한다. Absolute → Smoothstep(0.54, 1) → One Minus를 Alpha에 사용한다. 전류 떨림은 높은 공간 주파수의 사인 두 개를 곱하거나 Gradient Noise를 작게 넣는다. 중심 HDR 출력은 `_Signal × Max(0.35, _Energy) × (0.52 + 0.72 × pulse)`다. 피복은 별도 일반 알파 패스로 그려 밝은 배경에서도 남긴다.
3. **플러그.** 필라멘트 마스크를 원화와 같은 사각형·피벗으로 올리고 Sprite Texture의 RGB와 Renderer Tint, HDR 색, `_Intensity`를 곱한다. 알파는 마스크 A × Tint A다. Additive 블렌딩을 쓰고 헤드 원화는 Alpha 블렌딩으로 둔다. 핀과 고무까지 마스크에 들어가면 소형 화면에서 흰 덩어리로 보인다.
4. **블룸.** URP라면 카메라 Post Processing과 HDR을 켜고 Renderer의 HDR 설정, 실제 카메라의 Volume Layer Mask를 확인한다. 시작값은 Threshold 1.1, Intensity 0.20, Scatter 0.55. 꽂힘 순간은 로컬 마스크가 먼저 빛나야 하고, 볼륨을 더 쓰더라도 짧은 가중치 변화만 준다. 전체 레벨의 다른 공격 예고가 씻겨 나가면 카메라 플래시를 먼저 줄인다.

### 비용과 검증

`sharedMaterial`을 공유하고 전선·필라멘트에 재사용하는 MaterialPropertyBlock으로 값만 바꾼다. 이 방식은 개별 재질 인스턴스 생성을 피하지만 MPB가 적용된 Renderer는 일반적으로 SRP Batcher 경로에서 제외될 수 있다. 모든 방의 모든 소켓에 매 프레임 재질 복사본이나 MPB를 만들지 않는다. Frame Debugger에서 실제 배치와 패스를 확인한다. 저품질에서 비행 트레일과 이동 잔상·도킹 불꽃·선택형 점광원을 끈 뒤에도 핀 간격·화살표·호가 읽혀야 한다.

**V5 확인.** 흰 셔터, 어두운 골목, 파란 입자 위에서 회전과 도킹을 각각 촬영한다. 완충 시 핀 사이가 여전히 갈라져 보여야 하고, Flat/Low에서도 연결·차단을 구별해야 한다. 도착 즉시 전선은 없어지고 해당 지점의 작은 임팩트만 남아야 한다. 프로파일러에서는 첫 생성 후 60초간 반복해 드로콜·할당·프레임 시간을 측정한다. 흔한 실수는 HDR 색을 LDR 출력에 미리 Clamp하거나, 선 UV를 길이 정규화 없이 원거리에서 늘리거나, 재시도 전에 트레일을 지우지 않아 다음 방까지 한 줄이 이어지는 경우다.

원화·프롬프트와 상태별 시인성 기준은 [아트 바이블](BLUE_PLUG_ART_KO.md)에, 실제 신호음과 영상의 시간 관계는 [효과음 설계](BLUE_PLUG_SOUND_KO.md)에, 플레이테스트 기록 방식은 [통합 검수표](BLUE_PLUG_QA_KO.md)에 있다.
