# 파란 플러그 P2′ · V7 시각·입력 검수

이 문서는 **실제 Unity Play Mode에서 수행할 검수 절차**다. 현재 작업 환경에는 Unity Editor가 없어 아래 항목의 네이티브 통과, 실제 FPS, GC 수치나 시인성을 확인했다고 보지 않는다. 순수 규칙·대역 기반 검사 결과와 실제 화면·Input System·물리 검증 결과를 따로 기록한다.

## V7에서 확인할 그림

타이틀의 **파란 플러그 시험 · 빨래골목**에서 생활층 벽 콘센트 길 11번을 연다. 출입구의 두 정비대에서 E로 스킬을 배운다. 블레이드 미장착 상태에서 좌클릭 홀드로 회전하고 놓아 투척한다. 소켓에 꽂힌 뒤 C를 새로 누르면 견인, V를 새로 누르면 스윙한다. 스윙 중 V는 접선 이탈, G는 회수다. 벽 붙기는 몸이 실제 고정대에 닿았을 때 벽 쪽 방향키를 눌러 시험한다. 투척이 실패하면 체결음과 섬광이 없어야 한다. 체결과 견인 도착에서는 각각의 효과가 한 번씩 발생해야 한다. 블레이드 장착 중 좌클릭 공격, 일반 대시, 우클릭 수집도 함께 확인한다.

실제 화면을 기록하려면 방에 들어간 후 **PLUGIN → P2 → 실제 플레이 플러그 촬영 시작·종료**를 누르고 Game 뷰에서 플레이한다. Console에 출력된 `PlugCaptures` 경로에서 상태별 PNG를 확인한다. 같은 메뉴를 다시 누르면 촬영이 끝난다. **PLUGIN → P2 → 플러그 양손·전선 연출 검사**는 임시 검사 오브젝트로 동일한 부품을 검사한다.

### 같은 줌에서 찍을 세 장면

1. **빨래골목 두 갈래**에서 같은 위쪽 소켓을 겨눈다. 첫 시도는 체결한 채 걸어본 뒤 C로 옥상에 도착한다. 두 번째는 턱 오른쪽에서 V로 매달려 D로 진행하고, 노란 차양 아래 수선집 창문 앞에서 V를 다시 눌러 놓는다. 벽 소켓에 몸이 닿았을 때 벽 쪽 방향키와 Space로 붙기·이탈을 따로 찍는다.
2. **Main → 0 → 17287 → 보스 → 조직 본거지 · 경비대**에서 검은 장갑과 주황색 칼날, 적갈색 망토를 두른 기존 LANCER를 찾는다. 백 경위는 입자 20개로 Q를 눌러 블레이드를 소환하고, 꽂힌 손잡이를 겨눠 좌클릭으로 플러그를 체결해 장착한다. 적 바깥에서 한 번, 같은 방향으로 접근해서 한 번 벤다. 경비의 칼끝과 망토, 백 경위의 앞발과 손잡이, 타격점의 스파크를 함께 본다. 드론의 조준·발사 자세도 여기서 확인한다.
3. **Main → 0 → 17287 → 보스 → 조커 · 최상층 저격수**에서 1페이즈의 견착과 다섯 발 뒤 장전, 거리를 벌렸을 때의 수류탄 투척을 찍는다. 4~5페이즈의 일반 레이저는 넓힌 양발과 낮춘 중심으로 구별한다. 일반 공격 검수는 5페이즈에서 끝낸다.

세 장면 모두 Play 중 **PLUGIN → P2 → Game 뷰 3초 연속 촬영**을 누르고 1.5초 안에 Game 뷰로 돌아오면 현재 구도를 PNG 시퀀스로 저장한다. 소리는 Play 중 따로 듣는다. 촬영 시마다 Console에 출력되는 경로와 시작 해상도를 기록한다.

보스의 복식과 실루엣을 비교하려면 같은 개발자 메뉴에서 **기록 집행관**, **조커 · 최상층 저격수**, **비서실장 · 시계 전투**를 각각 선택한다. 집행관은 쇳덩이가 떨어지고 모습을 드러낼 때 전면 가면, 투명한 홀로그램 서류와 기계 장갑을 본다. 조커는 서 있을 때의 키와 조준·장전 사이의 상체 높이, 소총의 방향을 비교한다. Game 뷰의 해상도와 확대 비율은 세 장면에서 같게 둔다.

견인 잔상은 실제 백 경위 본체의 뒤집기, 회전과 월드 크기를 복사한다. 일반 맵의 두 견인 자세에서는 `BluePlugOfficer` 시트에 양팔·장갑·릴까지 합성한 전신 두 장을 사용한다. 전신과 본체는 각각 256×256, 110 PPU이며 힙 피벗도 같다. 손의 세부 각도는 각 견인 키포즈를 따른다. 기존 분리 몸통은 해당 `AncientArt.Swing` 전신에 연결된다. Play Mode의 **PLUGIN → P2 → 플러그 양손·전선 연출 검사**에서 두 일반 자세와 기존 자세의 대응, 반복 호출 시 같은 잔상 스프라이트 재사용을 검사한다.

잔상은 `BluePlugSilhouette` 셰이더로 원화의 알파만 읽고 이동 공통색 `#5CCBFF`를 입힌다. 붉은 스카프와 흰 제복의 RGB가 잔상색에 섞이지 않는다. 불꽃은 흰 픽셀에 같은 색을 곱한다. 셰이더를 지원하지 않는 환경의 대체 렌더링은 실제 화면에서 따로 확인한다. 컴포넌트 하나가 만든 실루엣 재질 하나를 여섯 잔상이 공유하며, 개별 샘플마다 재질을 만들지 않는다.

견인 중에만 잔상을 만들고, 스윙·준비·투척·회수에서는 새 잔상을 만들지 않는다. 풀은 본체 복사본 6개와 불꽃 16개로 고정된다. 풀 루트 1개를 포함한 GameObject는 23개이며, 런타임에 잔상이나 불꽃을 추가 생성하지 않는다. 도킹 불꽃 6개와 도착 불꽃 8개는 같은 풀을 재사용한다. 섬광 줄임에서는 2개와 낮은 불투명도를 사용하며, 저품질에서는 새 효과와 남은 효과를 숨긴다. 효과는 화면 주변 12% 범위 밖에서 새로 생성하지 않는다.

연결할 API는 `Bind(bodyRenderer, camera)`, `SetTowing(bool)`, `Latch(point, normal)`, `Arrival(point, incoming)`, `Clear()`다. `Bind`는 플러그 헤드나 그림자 대신 **실제 백 경위 본체**를 받아야 한다. 외부 설정 UI가 옵션을 바꾸면 `RefreshPreferences()`를 호출한다. 일반 F5/F6 변경과 포커스 복귀는 컴포넌트가 확인한다. 재시도·방 전환·피격으로 세션을 버릴 때 `Clear()`가 남은 효과도 정리해야 한다. `ActiveAfterimages`, `ActiveSparks`는 실물 검수용 읽기 전용 수치다.

Inspector의 `afterimageLife` 기본값은 0.15초, `afterimageInterval`은 0.028초, `afterimageDistance`는 0.12 월드 단위다. 수명을 늘리거나 간격을 줄여도 풀은 6개로 유지하고 가장 오래된 샘플을 재사용한다. 초기 `Bind`에서 여덟 완전한 프레임을 준비하며 지속 이동 중에는 프레임을 생성하지 않는다.

## 배경·흑백·색 충돌

생산구의 푸른 설비, 생활구의 노란 창문, 행정구의 청록 기록등, 거주구의 밝은 벽과 식물, 최상층의 어두운 창을 각각 사용한다. 같은 화면을 원색과 흑백으로 비교한다. 흑백에서는 후처리 또는 캡처 뷰어의 채도 0을 사용하고 게임 원본 텍스처를 바꾸지 않는다. 소켓이 알아볼 만한지는 색뿐 아니라 단자 두 칸, 윤곽, 준비 조준 문양, 차단 ×, 자물쇠와 움직임으로 판단한다.

아래 값은 소스의 기본 RGB를 8비트에 반올림한 값이며, 셰이더·알파 합성 후의 실제 화면 색이나 대비비를 뜻하지 않는다.

| 대상 | 기본 색 | 실제 충돌 위험과 검수 기준 |
|---|---|---|
| 전선 중심 | `#5CCBFF` | 파란 입자 `#1F8CFF`와 겹친다. 전선의 연속 선과 입자의 분리된 점이 구별돼야 한다. |
| 소켓·준비 표시 | `#5CCBFF` | 청록 설비와 경위의 팔이 비슷하다. 준비 여부는 색 변경에 의존하지 않고 조준 문양·발광 세기·단자 홈으로 구별돼야 한다. |
| 고속 전선 발광 | `#5CCBFF` + 셰이더 세기 | 흰 제복·밝은 벽에 묻힐 수 있다. HDR·블룸 결과가 희게 보이더라도 어두운 전선 외곽과 플러그의 형태를 확인한다. |
| 잠긴 기술 | `#6978AD` | 그늘 속 청회색과 합쳐질 수 있다. 자물쇠 실루엣이 남고 준비 조준 문양과 혼동되지 않아야 한다. |
| 차단 표시 | `#FF9947` | 노란 블레이드와 주황 공격 예고에 겹친다. × 형태로 차단을 읽고 공격 범위나 목표 지점으로 착각하지 않아야 한다. |
| 견인 잔상·불꽃 | `#5CCBFF` | 소켓·전선과 같은 공통색이다. 잔상은 본체 뒤의 짧은 실루엣, 불꽃은 접점의 짧은 방사선으로만 읽혀야 한다. 소켓 상태나 적의 공격 예고를 덮으면 실패다. |

고품질과 저품질, 섬광 기본과 줄임을 각각 비교한다. 후광을 끄거나 흑백으로 바꿔도 연결 가능 여부와 견인·스윙 문양이 남아야 한다. 작은 창과 1280×720, 1920×1080에서 같은 단자가 보이는지 확인한다. 접근성이 확보됐다는 결론은 실제 캡처와 관찰 기록 뒤에만 낸다.

## 0.25배속과 프레임 순서

별도 QA 세이브에서 본편과 빨래골목을 실행한다. 원래 `Time.timeScale`과 `Time.fixedDeltaTime`을 적어 두고, 첫 검사는 timeScale만 `0.25`로 바꿔 렌더 프레임 사이 물리 틱이 없는 경우도 관찰한다. 두 번째 검사는 원래 고정 간격의 0.25배를 사용해 같은 물리 틱 수의 동작도 비교한다. 검사 후 두 값을 반드시 복원한다. Editor Pause와 Step으로 상태를 읽되, **한 번의 Editor Step이 입력·Update·FixedUpdate를 모두 한 번씩 실행한다는 가정은 하지 않는다.**

Input Debugger와 Inspector 또는 임시 QA 로그에서 입력 프레임, 회전 시작, 릴리즈의 충전량, `Flying`, `Connected`, C/V의 새 입력 프레임, 이동 시작, 완료/회수 순서를 대조한다. 접속 프레임까지 누르고 있던 C/V가 자동 이동을 만들면 실패다. 릴리즈 직후 첫 물리 틱에 비행 상태로 바뀌어야 한다. 잔상은 자세 적용 뒤에 기록돼야 하며 이전 걷기 프레임이나 플러그 헤드가 복사되면 실패다.

## 필수 검사 10개

P0는 충돌 우회·진행 불가·입력 오작동으로 배포를 막는다. P1은 기능 또는 상태를 잘못 읽게 하는 결함으로 배포 전에 고친다. P2는 시각 품질과 성능 개선 항목이며 반복 발생하면 P1로 올린다. 아래는 수행할 검사 목록이며 통과 기록이 아니다.

| 8 | P1 | 다섯 구역의 밝은/어두운 배경에서 원색·흑백 비교, 작은 창과 두 표준 해상도 | 조준·차단·잠금·연결을 모양으로 구별한다. 잔상과 불꽃이 전선, 입자, 적 공격 예고와 소켓 문양을 가리지 않는다. 화면 밖 접점이 화면 안에 가짜 불꽃을 만들지 않는다. |

| 10 | P2 | 10회 준비 후 60초 견인·도킹·회수 반복, 방 왕복 20회. Profiler와 Frame Debugger 관찰 | 이 컴포넌트의 풀은 본체 6·불꽃 16을 넘지 않는다. 정상 이동의 `LateUpdate`에서 관리 힙 할당 0 B/frame을 목표로 확인한다. 재질 인스턴스와 GameObject 수가 반복마다 늘지 않고 방 종료 후 풀 루트가 정리된다. 프레임 시간·드로콜은 기본/저품질을 각각 기록한다. |

## Profiler 기록과 보고

Development Build 또는 Editor Play에서 CPU Usage의 GC Alloc 콜스택을 확인한다. 처음 풀·텍스처·공유 재질을 만드는 비용은 준비 구간에 따로 적고, 60초 샘플에는 키 입력과 장면 조건을 붙인다. Deep Profile은 호출 위치를 찾는 보조 자료로만 사용하며 그 프레임 시간을 일반 실행 성능으로 보고하지 않는다. `AncientGame.Saved`의 문자열 키 생성, 기존 오디오·다른 게임 효과의 할당과 `BluePlugTravelFX` 자체 비용을 구별한다. 옵션 변경·포커스 복귀 때의 설정 읽기도 지속 이동 샘플과 분리한다.

보고에는 빌드/커밋, Unity 버전, 화면 크기, 구역·소켓, 품질·섬광 설정, 타임스케일, 실제 입력 순서, 실패 프레임을 남긴다. P0/P1 실패가 있으면 재현 절차와 기대/실제 결과를 붙인다. 파일 기반 검사만 완료한 경우에는 **실물 미검증**으로 기록하고 FPS·완성도 수치를 추정해 넣지 않는다.

## 첫 플레이 뒤 플레이테스터에게 물을 질문 10개

처음에는 조작의 정답이나 장면의 의도를 설명하지 않고, 한 번 플레이한 뒤 아래 질문을 한다. 답을 유도하는 선택지나 예시는 먼저 주지 않는다. 기억나지 않는다는 답도 그대로 기록하고, 플레이어가 말한 장면을 나중에 녹화와 대조한다.

1. 처음 화면을 봤을 때 무엇을 먼저 해 보려고 했나요?
2. 어디에 연결할 수 있다고 생각했고, 그렇게 생각한 이유는 무엇인가요?
3. 버튼을 누를 때, 누르고 있을 때, 놓을 때 각각 어떤 일이 생길 거라고 예상했나요?
4. 회전과 투척 장면에서 왼손과 오른손은 각각 무엇을 하고 있었다고 기억하나요?
5. 플러그가 꽂힌 상태와 몸이 이동하는 상태를 어떻게 구별했나요?
6. 짧게 눌렀을 때와 길게 눌렀을 때 어떤 차이를 느꼈나요?
7. 투척이 실패하거나 플러그를 회수한 뒤 다시 시도할 때 어떤 일이 있었나요?
8. 소켓의 문양이나 불빛이 바뀌었을 때 각각 무슨 뜻이라고 생각했나요?
9. 이동 중 자신의 몸, 목표 지점, 주변 지형을 구별하기 어려웠던 장면이 있었나요?
10. 조작이나 화면 효과에서 헷갈리거나 불편한 점이 있었다면 무엇인가요?
