# 백 경위의 동작과 기록 집행관 등장 연출

## 게임에서 확인하기

`Main.unity`를 열고 `PLUGIN > 검사 > 기록 집행관 바로 플레이`를 선택한다. 백 경위가 출구로 달려가다 쇳덩이 아래에서 몸을 낮추고 뒤로 뛰어 착지한다. 접근은 이동 거리에 맞춰 발을 바꾸고, 어깨가 먼저 기울며, 충격 직전 두 발이 바닥에 닿은 뒤 0.22초간 제동한다. 판정 캡슐과 발을 그린 스프라이트 자식은 독립적으로 움직인다. Space를 새로 0.6초간 누르면 오른쪽 아래 표시가 차면서 컷신을 건너뛴다. 전투 시작 후에는 사령관의 첫 낙하 안내가 무전기로 나온다. Backspace를 한 번 누르면 현재 무전 페이지가 즉시 펼쳐지고, 다 읽은 페이지에서 누르면 다음으로 넘어간다.

`TraversalRhythmPractice`에서는 같은 걷기·착지 계산을 사용한다. 대시 중에는 상체를 앞으로 낮추고, 벽을 짚은 자세에서 벽 점프로 밀어내면 어깨가 반대편을 향한다. 직선 갈고리를 쏘면 와이어 발사 자세를 취한다. P1/P2 입력과 본편 입력은 현재 별도이므로 각 장면에서 검사한다.

## D2 · 동작 제작표

수치는 **본편**, **연습**, **제작안**을 구분한다. 제작안은 아직 전투 입력이나 판정에 연결되지 않은 포즈의 제작 기준이다. 프레임 수는 원화 포즈 개수다. 60Hz에서 매 프레임 보간하는 발 피벗, 카메라, 잔상은 별도로 계산한다.

`AncientBladeRules`가 대미지와 애니메이션의 시간을 함께 제공한다. 105ms에서 225ms로 렌더가 건너뛰더라도 예약된 1타 명중은 한 번 소비된다. 베기 도중 같은 공격 버튼을 또 눌렀을 때 남은 시간을 검사한다. 첫 입력 즉시 대기 자세를 취하는 것과 다음 타격이 실제로 확정되는 시점은 따로 기록한다.

**모션 원화 제작 규칙.** 전구가 달린 손의 시작·끝 위치로 주동선을 먼저 잡는다. 공격 전에는 실루엣의 빈 공간이 접히고, 베는 동안 팔이 먼저 펴지고, 어깨와 외투 자락은 1~2포즈 늦게 따라온다. 평상시는 12fps에 해당하는 유지 시간을 출발점으로 잡고, 짧은 예고·날끝 교차는 24fps 이상 간격으로 세분화한다. 본편 16포즈 콤보는 위 시간표에 맞춰 샘플링한다. 캐릭터 음영은 일관된 흑백 면, 전구는 노랑, 집행관 장치는 하늘색 직사각형을 기본으로 한다. 집행관의 위협은 렌즈 한 점 외에도 어깨 높이, 조형하는 손의 음각, 바닥 예고로 읽혀야 한다.

**Animator를 도입할 때.** 현재 본편은 코드가 스프라이트를 선택한다. 스프라이트 전체가 한 장인 동안은 `AncientLocomotionMotion`, `AncientBladeRules`, `DistrictPlayerPresentation`에 상태별 표현을 모으는 편이 타격 판정과 맞는다. 몸과 서브무기를 분리한 아틀라스를 만들 때는 Base(다리·몸통), Upper(갈고리·공격·수집), Bulb(발광), Equipment(무기 유무) 순서로 자식 렌더러를 나눈다. 2D 스프라이트 한 장을 그대로 겹치면 다리가 두 벌 그려진다. 상태 진입은 즉시 `Animator.Play`하고, 관성 때문에 연결이 필요한 착지와 대기만 짧게 CrossFade한다. 입력을 받는 전환은 Has Exit Time을 끈다. 모드 전환시 갈고리의 열려 있는 손과 공격의 들어 올린 날을 교체하되 달리는 발 위상은 유지한다.

**프레임 이벤트.** 피봇·무기·날끝의 좌표를 양방향으로 기록한다. Animation Event는 섬광·발소리·잔상 알림에 쓴다. 콤보 취소나 스킵 뒤에 늦게 도착한 이벤트는 공격 일련번호로 버린다. 대미지와 Hitbox 종료는 상태 소유자가 현재 시간으로 결정하고 Exit에서도 비운다. 같은 대상의 한 타격을 이벤트와 물리 양쪽에서 적용하지 않는다.

## D3 · 컷신 제어

`AncientEnforcerIntro`가 등장 동안 `InputLocked`를 제공하고 `AncientGame.Paused`가 일반 이동과 물리 입력을 막는다. `AncientEncounterCutscene.Enter`는 원래 Rigidbody2D 타입·보간·시뮬레이션 여부를 기록한다. 와이어와 진행 중 공격을 해제하고 Kinematic, None, simulated=false로 전환한다. 연출은 `Update`에서 계속 움직이고 `LateUpdate` 카메라는 같은 시각의 좌표를 읽는다. `EndIntro`가 건너뛰기와 정상 종료의 공통 도착점이다. 마지막 배우 위치와 카메라를 정하고 물리 설정을 복구하며 입력을 한 프레임 여유를 두고 연다. 보스가 제거되는 경로도 `StopBattle`에서 소유권을 풀어 준다. 입자 보유량과 모드는 컷신이 건드리지 않는다. 진행 중 홀드와 준비 중 공격은 취소된다. 향후 P5를 연결할 때는 장착/꽂힘 상태와 현재 대상을 무기 소유자에게 남겨야 한다.

|---|---|---|

**Timeline 제작 순서.** 현재 manifest에는 Timeline과 Cinemachine 패키지가 없다. 도입 시 전용 `PlayableDirector`를 만들고 Unscaled Game Time을 설정한다. (1) Activation은 배경 장치와 이펙트 자식만 제어한다. (2) Animation 트랙에는 물리를 중지한 배우의 연출용 피벗을 바인딩한다. (3) Cinemachine 트랙에는 접근·충격·렌즈·전투장 사이즈를 각각 기록한다. 카메라 Brain과 배우가 같은 렌더 프레임을 사용하도록 Late Update에서 확인한다. (4) Signal로 단발 충격음과 파편 풀을 호출한다. (5) Audio 클립은 외부 메뉴 정지 시 Director와 함께 정지한다. 컷신 세트를 프리팹으로 복제하고 배우·카메라·오디오를 인스턴스마다 바인딩한다. 자막이나 문 개방은 `stopped`와 스킵의 동일한 완료 함수에서 처리한다. 이미 지나간 시그널을 강제 재생해 완료 상태를 구성하지 않는다.

**코드 이동을 추가할 때.** 현재 쇳덩이는 중력 가속처럼 진행률의 제곱을 쓰고, 인물·카메라는 양 끝 속도가 0이 되는 SmoothStep을 쓴다. 이동 거리의 20% 지점에서 발이 닿으면 보간된 실제 거리가 그 지점을 지나는 프레임에 접지를 발생시킨다. 독립 소품 하나를 Unity 6의 Awaitable로 움직여야 할 때 쓸 수 있는 형태다. 스킵·파괴 시 소유자가 토큰을 취소하고 공통 완료 함수를 호출한다.

```csharp
using System;
using System.Threading;
using UnityEngine;

public static class CutscenePropMovement
{
    public static async Awaitable MoveAsync(Transform prop, Vector3 start, Vector3 end,
        float seconds, AnimationCurve easing, Func<bool> paused, CancellationToken lifetime)
    {
        float elapsed = 0f;
        while (elapsed < seconds)
        {
            await Awaitable.NextFrameAsync(lifetime);
            if (!prop) return;
            if (paused != null && paused()) continue;
            elapsed += Time.unscaledDeltaTime;
            float t = Mathf.Clamp01(elapsed / seconds);
            float eased = easing == null ? Mathf.SmoothStep(0f, 1f, t) : easing.Evaluate(t);
            prop.position = Vector3.LerpUnclamped(start, end, eased);
        }
        lifetime.ThrowIfCancellationRequested();
        if (prop) prop.position = end;
    }
}
```

**무전 편집.** Project에서 `Create > PLUGIN > 무전 대사`를 고른다. `Assets/Resources/Radio/EnforcerEntry.asset`에는 사령관과 첫 경고 한 줄이 들어 있다. 일반 대화는 화자 옆 말풍선, 무전은 무전기 그림과 한 글자씩 나타나는 말풍선을 쓴다. 공간을 많이 차지하는 설명은 보스가 공격하기 전에 나눠 둔다. 이동·전투와 동시에 나오는 무전은 Backspace로 넘긴다. 주민 대화의 Space/Enter는 기존 동작대로 작동한다.

## 에디터 검수

1. Main에서 원속도 및 120fps 녹화의 1/4속도로 접근·점프·착지를 프레임 단위로 본다. 발 피벗을 월드 바닥과 대조한다. 입력→첫 포즈, 입력→물리 이동을 서로 다른 프레임 번호로 기록한다. 키와 화면을 함께 촬영할 수 있으면 240fps에서 1프레임이 4.17ms다. 녹화 FPS만으로 실제 입력 지연을 단정하지 않는다.
2. Space를 누른 채 진입, 0.2초 탭, 새로 0.6초 홀드, 홀드 중 Escape·포커스 이탈과 복귀, 자연 종료를 각각 검사한다. 마지막 경우를 포함해 전투 시작 위치와 보스 HP가 같아야 한다. 약점·위험 표시가 입력 복귀보다 늦으면 첫 피해 판정 시간을 확인한다.
3. 진입 전 와이어 모드와 공격 모드, 입자량 0·40·85를 각각 기록한다. 종료 후 보유량과 모드, Dynamic/Interpolate/Simulated 원복, 이동·점프·공격·무전 동시 입력을 본다. 스킵용 Space가 첫 프레임 점프로 재사용되면 입력 잠금 경계를 점검한다.
4. 4:3·16:9·21:9에서 충격과 회피가 같은 샷에 들어오는지 확인한다. Dolly 구간에서 카메라를 인물보다 늦게 흔들지 않고, 착지 순간에만 짧게 충격을 준다. 글자 가독성이 떨어지면 해당 샷의 배율과 자막 안전 여백을 조정한다.
5. 연습 씬에서 좌우 벽 점프, 0에 가까운 거리의 돌진, 수직 돌진, 착지 직후 재돌진을 시험한다. 시각 변형 전후 이동 거리·콜라이더 폭이 같아야 한다. 각 장면의 실제 플레이 성능과 렌더 결과는 Unity 에디터에서 측정한다.
