# D1 · 백 경위와 기록 집행관의 시각 설계

기록실 문을 열었을 때 가장 먼저 보여야 하는 것은 떨어질 쇳덩이의 **착지 폭**이다. 다음 시선이 쇳덩이를 만든 **한쪽 기계장갑**으로, 마지막 시선이 장갑을 조작한 **젊은 현장 집행관의 단안 렌즈**로 옮겨가게 한다. 그의 서류철은 신분을, 하늘색 사각 입자는 조형 능력을 설명한다. 퇴장 때도 같은 장비를 알아볼 수 있어야 2회차의 재등장이 이어진다.

이 문서의 색·거리·시간은 제작 시작값이다. 현재 프로젝트는 Unity 6000.6.7f1, 스프라이트·LineRenderer·자체 발광 재질을 쓴다. Packages/manifest.json에는 URP 의존성이 없다. 아래 URP 2D 절차와 Shader Graph 사양은 선택 적용을 위한 설계다. 본편의 자료·입력·저장과 별도로 미리보기 씬에서 검증할 수 있다.

## 한 사람이 유지할 수 있는 아트 방향

| 방향 | 전구·샤프심을 어떻게 그리는가 | 장점 | 비용과 약점 | 1인 개발 판단 |
| --- | --- | --- | --- | --- |
| 명암 세 덩어리의 픽셀아트 | 검은 기계 팔뚝, 흰 견갑, 얇고 긴 황색 칼날. 전구 내부 필라멘트가 단계마다 하나씩 켜진다. | 기존 백 경위와 실루엣·스프라이트 재사용. 원거리에서도 칼 방향과 몸이 읽힌다. | 대각선·발 접지·머리 비율을 포즈별로 직접 정리한다. 중간 난도. | **채택.** 캐릭터를 먼저 완성하고 필요한 광원만 겹칠 수 있다. |
| 하이콘트라스트 판화 | 발광 면이 검은 형상에 홈을 파듯 드러난다. 전구는 흰 음각 원, 샤프심은 칼끝의 가는 선이다. | 역광 컷신·포스터를 빠르게 만들고 아군/적 윤곽이 강하다. | 중간 명암이 적어 손·문서·장갑을 구분하기 어렵다. 낮은~중간 난도. | 보스 등장 첫 역광 한 컷에 도입. 장시간 전투에는 몸 안 명암 보강. |
| 네온 설계도 라인아트 | 필라멘트 회로와 연필심 축을 도면선으로 잇고 입자가 부품을 조립한다. | 조형·흡수의 방향, HUD 기기 도식에 적합하다. | 확대·축소 시 가는 선 떨림과 과도한 발광. 장면마다 광량을 맞춰야 한다. 높은 난도. | 전체 캐릭터 제작보다 조형 예고와 무전기 화면에 한정하면 유지 가능. |

**제작 규격.** 신규 필드 도트의 기준 캔버스는 640×360, x2·x3 정수 확대에서 먼저 판독한다. 캐릭터별 원화 PPU는 기존 엔진의 발바닥 기준과 월드 키를 유지하고 출력 화면에서 비교한다. 집행관 고해상도 여섯 포즈는 기존 슬라이스·피벗을 보존하거나 실제 부츠 위치에서 다시 측정한다. 몸의 검정/흰 부분을 넓은 면으로 나누고 전경 외곽은 기준 화면 2px, 내부 구조는 1px를 시작값으로 한다. 코·턱·서류철 모서리는 한 번만 꺾고, 기계 부품의 사면은 최소 2×2px로 남긴다. 일반 캐릭터당 주색·음영·보조색을 합쳐 12~16색, 광원 최대 밝기는 무기나 단안 렌즈 한 곳에 쓴다. 기존 고해상도 배경에 적용할 때는 최종 해상도에서 명암 집단 수를 맞춘다.

### 앵커 6종 도안

고정·일회용·이동형은 연습 씬의 기존 기믹에 맞춘 도안이다. 예측·반사·에너지 앵커의 동작과 도안은 구현 후보로 둔다. 외곽 크기·클릭 중심은 같은 축척을 쓰고 후보가 되면 바깥 괄호 두 개만 좁힌다.

| 종류 | 형태 | 색과 애니메이션 |
| --- | --- | --- |
| 고정 | 원형 철제 소켓, 비어 있는 둥근 중심 | 청록, 움직임 없이 고정. |
| 일회용 | 한 귀퉁이가 깨진 삼각 고리 | 청록+엷은 황색, 예약되면 균열을 한 방향으로 번지게 한다. |
| 이동 | 육각 고리와 양옆 레일 날개 | 청록+백색, 왕복 레일에 작은 홈을 두고 정지점에서 끝 마커를 켠다. |
| 예측 | 고리와 미리 찍힌 점선 반고리 | 옅은 민트, 미래 도착점에 한 번만 잔상이 붙는다. |
| 반사 | ㄱ자 쐐기와 한 방향 화살 | 연두빛 청록, 화살만 탈출 방향으로 흐른다. |
| 에너지 | 두 겹 사각 고리와 중심 번개 | 흰 청록, 외곽에서 안쪽으로 두 번 수축한다. |

### 보스·예고·배경 대비

보스 크기로 축소한 흑백 캡처에서 장갑과 얼굴이 서랍 배경 위에서 하나로 붙으면, 그 뒤의 밝은 서랍 한 묶음만 어둡게 한다. 카메라가 멀어질수록 얼굴보다 팔·서류 실루엣의 간격이 먼저 읽혀야 한다. 기록실의 천장 조명은 조준 표식에서 벗어난 위치에 둔다.

| 상황 | 먼저 보일 표식 | 시간·고정 규칙의 시험값 |
| --- | --- | --- |
| 낙하·하드드랍 | 바닥 양 끝 괄호가 실제 착지 폭을 감싼다. 집행관의 조형 입자는 위에서만 모인다. | 일반 550~750ms, 빠른 변형은 처음 제시한 뒤 350~450ms부터 검사한다. 마지막 150~200ms에 위치를 잠근다. |
| 방향성 파도·선형 빔 | 시작 쪽에 큰 진행 삼각, 맞은편 안전 바닥에 연속 수평선 | 예고 650~900ms. 이동에 필요한 시간이 더 길면 실제 이동거리와 가속으로 예고를 연장한다. |
| 3페이즈 반격·광역 흡수 | 반격은 한 번의 잠금음과 조준선, 흡수는 중앙으로 향하는 직사각형과 천장 물체의 균열 | 반격은 실제 회피 가능 시간을 입력 해제 시점부터 잰다. 흡수의 기존 15초 동안 마지막 3초에만 경고 박자를 올린다. |
| 약점·스턴 | 깨어진 보호판 두 조각, 호흡하듯 켜지는 빈 고리 | 위협이 끝난 직후부터 반격창 끝까지 유지한다. 열린 상태를 매 프레임 깜박이지 않는다. |

## 캐릭터 변형과 약점 설계

**백 경위 후보.** 세 안 모두 무표정이 드러나지 않는 챙, 흑백 면 분할과 금빛 전구 블레이드를 유지한다.

| 안 | 한눈에 읽히는 실루엣 | 전구의 충전 표시 |
| --- | --- | --- |
| A · 비대칭 순찰복 | 흰 어깨와 검은 몸통, 큰 고대 기계팔 아래 길게 나온 곧은 칼날. 기존 주인공에 추천한다. | 손잡이 안의 평행 필라멘트 1·2·3개가 켜진다. 작은 노란 면이 마지막에 흰 중심을 얻는다. |
| B · 절연 장갑 순찰복 | 짧은 흰 망토, 긴 다리, 한 팔의 절연판 사이에 빛나는 심. | 가드의 세 창이 안쪽부터 차고 풀충전이면 고정된 테두리 하나가 둘러진다. |
| C · 보수반 잠입복 | 검은 어깨, 흰 하체와 장비 띠, 수평으로 단단히 잠기는 칼집. | 투명 원통 안의 심이 한 구획씩 점등한다. 투척 중에는 빈 소켓만 남는다. |

**보스 후보.** 첫 행은 이번 집행관의 디자인이고 나머지 둘은 별도 보스 제안이다. 약점 개폐를 판정에 연결하는 경우에만 반격색을 켠다.

| 후보 | 몸과 장비 | 1 → 2 → 3페이즈에서 약점이 읽히는 방식 |
| --- | --- | --- |
| 기록 집행관 | 젊은 얼굴, 짧은 짙은 머리, 단안 전술 렌즈. 체형은 유지하고 팔 장비의 비대칭, 몸통의 기술 장구, 서류철로 직책을 드러낸다. | 장갑에서 조형 → 팔 주변 장치의 작동 범위 확대 → 흡수 중 몸을 감싼 배리어 붕괴 뒤 스턴. 실제 저지 대상인 천장 낙하물에 균열을 그린다. |
| 필라멘트 검수기 | 긴 절연 세 다리와 노출된 전구 소켓 하나. | 몸통 보호 유리 → 과열 시 옆면 소켓 개방 → 양쪽 셔터가 번갈아 열려 다음 타격 면을 표시한다. |
| 흑연 압연기 | 낮은 궤도 몸통, 회전하는 심 드럼과 위쪽 편심 축. | 축 덮개 잠금 → 압연 후 비스듬히 열린 덮개 → 두 축 중 멈춘 축만 하얀 중심을 드러낸다. |

비서실장은 시곗바늘과 중앙 대칭 방사형을 쓴다. 집행관은 어깨에서 장갑으로 흐르는 비대칭 선과 적층 장비를 쓴다. 집행관의 기록철, 렌즈, 조형물에 시계 문자판·바늘·금빛 원형 장식을 반복하지 않는다. 파일럿 테스트에서는 얼굴을 가린 전신과 팔만 남긴 작은 이미지 두 장으로 두 인물을 구별하는지 본다.

## URP 2D 시험 적용

1. **기준 화면을 먼저 저장한다.** Unity 6000.6.7f1에서 기록실 첫 컷, 낙하 표식, 최대 레이저를 같은 해상도로 찍는다. 현재 추적 중인 설정과 패키지 상태를 저장하고 실험용 브랜치·시험 씬에서 시작한다.
2. **호환 버전을 Editor에서 선택한다.** Window → Package Management → Package Manager의 Unity Registry에서 Universal RP를 찾아 이 에디터에 호환되는 릴리스를 설치한다. Shader Graph 의존성이 함께 해결됐는지 확인하고 실제 설치된 manifest/lock을 기록한다. 특정 URP 버전을 임의로 고정하지 않는다.
3. **Renderer 2D 경로를 지정한다.** Create 메뉴의 URP Asset with 2D Renderer로 파이프라인 에셋과 Renderer 2D Data를 만든다. Project Settings → Graphics의 기본 파이프라인과 실험할 Quality 레벨의 오버라이드를 확인한다. 메인 카메라의 Renderer가 2D Renderer를 택하는지 본다. 이 설정은 프로젝트·품질 레벨 범위이므로 실험 브랜치에서 바꾼다.
4. **실제 불빛을 받는 대상부터 정한다.** 시험방 바닥·인물에 Sprite-Lit-Default를 적용하고 Global Light 2D 하나를 회청색, Intensity 0.35~0.55부터 적용한다. 전구 자식 Light 2D는 Point/Spot 계열의 전방향 설정, 바깥 반경 1.2~1.8 월드 유닛, Intensity 0.6~1.3부터 조절한다. 조명 Target Sorting Layers에 바닥·인물만 넣고 UI·경고선은 독립시킨다. 자식 광원을 끄고 바닥까지 밝기가 달라지는지 비교한다.
5. **가림과 재질을 소수부터 확인한다.** 큰 기둥 하나에 Shadow Caster 2D를 두고 실루엣 경로를 큰 모서리 위주로 맞춘다. 전구 Light 2D에 그림자를 켠다. 장갑 원화와 같은 크기의 접선 공간 노멀맵을 준비하고 Sprite Editor의 Secondary Textures에 `_NormalMap`으로 연결한다. 광원의 Normal Map 기능을 켜고 왼쪽에서 오른쪽으로 빛을 옮겨 돌출부 방향을 확인한다. 스프라이트를 런타임 Texture2D에서 생성하는 경로에는 Secondary Texture가 자동 상속되지 않으므로, 시험용 임포트 스프라이트로 먼저 검증한다.
6. **후처리는 카메라 한 대로 시험한다.** URP Asset·카메라에서 HDR 및 Post Processing을 켜고 Global Volume Profile의 Bloom(Threshold 약 1.0, Intensity 0.12~0.30), Vignette(0.10~0.16), Color Adjustments(Contrast +4, Saturation −5)를 시작값으로 한다. HDR 장갑·레이저 핵을 먼저 조절하고 Bloom을 마지막에 켠다. Chromatic Aberration은 평상시 0, 피격 시 0.06~0.10에서 약 80ms 동안 0으로 낮춘다. 감소 옵션에서는 수차·섬광을 끈다. 런타임에는 인스턴스 Volume Profile을 사용한다.
7. **본편 연결 전 확인한다.** 런타임의 `Sprites/Default`, 자체 발광 Shader, 런타임 생성 Sprite, LineRenderer를 분리해 색·투명도·분홍 대체 셰이더 발생을 확인한다. Built-in 카메라 콜백에 의존하는 `AncientDistrictBackdrop`도 SRP 카메라 렌더 이벤트와 카메라 필터를 검토한다. 한 빌드에서 4:3·16:9·21:9, Bloom 꺼짐/켜짐을 비교한다. 자세·충돌·이펙트 수명이 같고 성능 표본을 확보한 뒤 본편 이전 범위를 결정한다.

### Shader Graph 4종의 실제 연결

공통으로 URP Sprite Unlit 또는 Sprite Lit Graph를 만들고 Transparent를 쓴다. 사용 대상에 맞춰 Sprite Texture 샘플과 Vertex Color(스프라이트 틴트가 적용되는 경로)를 조합한다. Graph 타깃의 자동 틴트와 직접 곱이 중복되면 한 쪽만 사용한다. 아래 `baseRGB`, `a`는 스프라이트 원본 색·최종 알파다. 광원 영향이 필요한 몸통에는 Sprite Lit, 후광·경고·외곽에는 Sprite Unlit를 쓴다.

| 그래프 | 프로퍼티와 노드 연결 | 적용·검증 |
| --- | --- | --- |
| 피격 플래시 | `_Hit(0..1)`, HDR `_FlashColor`. Sample Texture 2D RGB → Lerp A, FlashColor → B, Saturate(Hit) → T, Lerp → Base Color. a → Alpha. | 피격 이벤트에서 Hit를 1로 올려 45~80ms에 0으로 내린다. 외곽 투명이 발광 사각형으로 변하는지 검사한다. |
| 파괴 디졸브 | `_Progress`, `_Band`, `_EdgeHDR`. 오브젝트 로컬 좌표 XY → Gradient Noise → Saturate로 n. `keep = step(Progress,n)`, `edge = keep × (1 − smoothstep(Progress,Progress+Band,n))`. Add(baseRGB, edge×EdgeHDR) → Base Color, a×keep → Alpha. | 0~1 중간 범위에서만 위 식을 쓰고 시작/끝에서는 온전히 보임/숨김으로 고정한다. 균열·부서지는 기물에 쓴다. 살아서 떠나는 집행관은 몸을 온전히 그린다. |
| 대상 아웃라인 | `_OutlineTexel`, `_OutlineColor`. UV에 텍스처 1px만큼 상·하·좌·우 오프셋 후 각각 알파 샘플 → Maximum 4개. `outline=saturate(maxNeighbor−a)`를 구해 원본과 선을 알파 합성한다. 출력 Alpha는 max(a,outline), RGB는 (baseRGB×a+lineRGB×outline)/max(Alpha,0.001). | 셀에 2px 이상 투명 여백, Full Rect 메시, Atlas 패딩을 둔다. 인접 프레임색이 보이면 셀 경계에서 UV를 클램프한다. 플레이어 조준 후보 1개에만 켠다. |
| 조형 배리어 오라 | 별도 자식 Quad/Sprite의 UV를 −1..1로 변환 → Length로 반경 r. Gradient Noise(UV×5 + Time×속도)로 반경을 약 ±0.02 흔든다. `ring = 1−smoothstep(width,width+feather,abs(r−radius))`. HDR 색 → Base Color, ring×세기 → Alpha. | 몸 외곽이 끝까지 남도록 오라를 뒤에 정렬한다. 섬광 감소 옵션은 noise 진폭·밝기만 낮추고 15초 충전 실루엣은 유지한다. |

공유 재질의 수치를 직접 바꾸면 같은 재질을 쓰는 다른 적도 번쩍인다. 개별 렌더러의 MaterialPropertyBlock 또는 소수의 공유 상태 재질로 전달하고, Frame Debugger에서 실제 배칭·드로콜을 비교한다. HDR, 투명 블렌딩, 보조 텍스처는 Player 빌드에서도 한 번씩 확인한다.

## 레이저·입자·배경

레이저는 LineRenderer를 사용하면 시작점과 실제 착탄점이 계속 바뀌는 본편 경로에 연결하기 쉽다. 판정 좌표를 먼저 정하고 **같은 두 좌표**로 코어·내부 글로우·외곽 오라를 갱신한다. 판정 폭을 1로 볼 때 코어 약 0.2, 몸통 약 1.0, 흐린 오라 약 1.4부터 잡는다. 바닥 표식과 겹칠 때 오라만 먼저 낮춘다. 재사용하는 발사구와 착탄 스프라이트를 양끝에 둬 다섯 층을 완성한다. UV의 폭 축에 Smoothstep 페이드, 길이 축에 흐르는 가는 필라멘트를 넣고 중심은 연속된 선으로 유지한다. 집행관의 조형 입자는 길쭉한 하늘색 직사각형으로 같은 점을 돌고, 플레이어의 마름모 입자는 수집 반경에서 캐릭터를 향한다. 작은 효과는 공유 재질·스프라이트 풀을 쓰고 실제 Light 2D는 대표 광원에만 붙인다.

| 배경 | 카메라가 1유닛 움직일 때 화면상 상대 이동¹ | 팔레트·배치 |
| --- | --- | --- |
| 원경 | 0.08~0.15 | 생산구의 탁한 황갈색 연기, 생활구의 자주빛 창문, 행정구의 푸른 회색 아치. 명암 차를 가장 낮춘다. |
| 중경 | 0.30~0.45 | 교각, 조명이 꺼진 주택, 기록실 서랍. 반복 무늬 밝기는 인물의 흰 면 아래로 제한한다. |
| 근경 | 0.75~1.00 | 길 가장자리 배관·난간. 주요 앵커 앞은 비워 둔다. 불투명 안개가 플레이어를 가리지 않게 한다. |

¹ 이 표의 1은 고정된 월드 지형처럼 화면에서 움직이고, 0은 카메라에 붙어 정지한 값이다. 재시도·순간이동은 레이어 오프셋을 즉시 초기화한다. 기존 본편은 층별 배경 한 장을 카메라에 맞춰 표시한다. 레이어 추가는 한 방에서 먼저 비교한다. 안개는 낮은 알파의 넓은 띠 1~2개, 먼지는 화면 밖에서 되돌리는 느린 점에 한정한다.

**외부 원화 없이 시작하는 방법.** 기록실 서랍은 어두운 직사각형 두 장과 밝은 윗변, 장갑은 사다리꼴 면 3개와 얇은 접합선, 경고선은 잠금 괄호 두 개로 회색조 시험방을 만든다. 형상이 읽힌 뒤에만 셰이더와 빛을 추가한다. 임시 소스는 Kenney의 해당 팩에 표시된 CC0 라이선스를 확인하고, OpenGameArt는 개별 작품별 라이선스·크레딧·배포 조건을 기록한다. 원본 URL, 작가, 라이선스 버전, 수정 내역과 고지 파일을 함께 보관한다. 저장소의 한글 폰트에는 자체 LICENSE.txt가 있다. ## HUD와 실기 승인 기준

- **모드와 무기 상태.** 갈고리 모드는 청록 열린 고리, 공격 모드는 짧은 황색 칼끝으로 조준점을 만든다. 충전량은 전구 안의 1~3개 필라멘트, 투척 후에는 빈 소켓, 폭발 회수 쿨다운은 꺼진 전구의 점진 점등으로 표현한다. 후자의 기능은 무기 상태 시스템과 연결될 때 표시한다. 화면 모서리에는 HP, 입자 수, 보스전 중 보스 HP만 상시 표시한다.
- **글자와 수치.** 기존 한글 NeoDunggeunmo 폰트를 유지한다. 1280×720 기준 HUD 본문 16~20px, 피격 수치 16px·약점 적중 20px부터 검사한다. 일반 피해는 짧게 위로 띄우고 동일 대상의 연속 타격은 약 120ms 동안 묶는다. 경고는 바닥과 궤도 가까이에 놓고 전신·발·안전 지대를 가리지 않는다.
- **확인할 장면.** 처음 보는 사람에게 소리를 끈 상태로 기록실 입장, 블록 착지, 배리어 차단, 집행관 퇴장을 보여 준다. “어디를 피할지, 무엇을 깰지, 누가 살아서 나갔는지”를 말할 수 있어야 한다. 이어서 4:3과 와이드 화면, 낮은 효과, 흑백 화면에서 파란 마름모와 하늘색 직사각형을 집어 보게 한다.
- **비용 확인.** 동일 기기의 동일한 탄막에서 F9/F10 출력과 Frame Debugger의 배치·투명 오버드로를 비교한다. 저품질 옵션은 오라·안개·먼지부터 줄인다. 판정에 필요한 중심선, 위험 경계와 안전 표식은 모든 품질 단계에서 유지한다. 실제 측정값은 D0 기록지에 적는다. [D0 플레이테스트](D0_PLAYTEST_KO.md)
