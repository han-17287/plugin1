# D7 · 기록실 전투의 프레임과 출시 점검

## 같은 장면에서 측정하기

`Main`을 열고 **PLUGIN → 검사 → 기록 집행관 바로 플레이**로 들어간다. 컷신의 쇳덩이 착지, 2페이즈 탄막, 3페이즈 X 블래스트, 흡수 중 광선을 각각 분리해 본다. 첫 로딩, 첫 패턴, 같은 패턴의 두 번째 실행, 재도전 10회 뒤를 표시한다. 같은 기기·해상도·프레임 제한·효과 설정을 사용한다. Editor의 QA 메뉴는 재현용이고 출시 후보의 성능 기준은 대상 PC Player 빌드에서 잡는다.

| 확인할 값 | 수집 | 판단과 후속 작업 |
|---|---|---|
| 프레임 시간·분산 | F8로 제한 선택, F9로 평균/P95/최대, F10으로 최근 240개 플레이 프레임 CSV 저장 | 60fps 예산은 16.67ms. 4초 이상 긴 구간을 60fps로 시험할 때는 Profiler 기록도 같이 사용한다. |
| 어느 패턴의 비용인가 | CSV의 `enforcer_phase`, `enforcer_move`, `enforcer_hazard_slots`, `enforcer_denied_spawns` | 페이즈 0은 전투 밖, move -1은 공격 사이. 0 낙하, 1 폭격, 2 사격, 3 파도, 4 블록, 5 복제, 6 비행기, 7 미사일, 8 흡수. 풀 칸은 할당된 수, 누락은 전투 시작 이후 공간 부족으로 거절된 생성 요청의 누계다. |
| GC | CSV `last_gc_bytes` 및 CPU Profiler의 GC.Alloc Call Stacks | 최근 완료 프레임의 할당량. F9가 닫혀 있었거나 카운터 미지원이면 -1이다. 최초 텍스처·효과 생성과 반복 중 할당을 분리한다. 진단 HUD와 CSV 저장 자체도 할당한다. |
| CPU 타임라인 | Development Build + Autoconnect Profiler. 초기 측정은 Deep Profile 끔 | `PLUGIN.Enforcer.Hazards`, `.Echoes`, `.Forge`를 펼쳐 스크립트·렌더러 갱신·Physics2D부터 분리한다. GPU 대기시간이 크면 Frame Debugger로 같은 장면을 캡처한다. |
| GPU·드로콜 | Frame Debugger에서 기록실 배경 → 직사각형 입자 → 광선 → 전체화면 효과 순으로 이벤트 확인 | 해상도를 절반으로 바꾸거나 F6로 효과를 바꿔 GPU 민감도를 본다. 밝은 화면, 정렬 순서, 광선 가장자리 겹침을 한 프레임씩 확인한다. |
| 메모리 | Memory Profiler 스냅샷을 입장 전, 1회 후, 10회 재도전 후 동일 상태에서 채취 | Texture2D/Material/SpriteRenderer/AudioClip의 누적과 소유자를 추적한다. 최초 공유 캐시와 퇴장 뒤 남은 인스턴스를 나눠 본다. |

F9 상세 기록을 켜면 재생 중인 집행관 등장 컷신도 표본에 들어간다. CSV의 `enforcer_intro=1`을 골라 전투와 구분한다. 기본 통계, 다른 컷신, 대화, 메뉴 및 포커스 상실 구간은 기존 조건을 따른다. 등장 전체의 CPU/GPU는 Unity Profiler 타임라인에서 읽는다. Recorder 부하가 있는 측정과 진단을 끈 Release 빌드를 한 번씩 비교한다. 시작 직후 한 프레임의 `last_gc_bytes`와 그 행의 패턴 사이에 약 한 프레임 오차가 있을 수 있다.

## 집중 점검 목록

| 영역 | 이 프로젝트에서 확인할 것 |
|---|---|
| 입자/위험물 풀 | `AncientEnforcerHazards` 상한 144, 복제 전용 탄환 32. 5배 확산탄과 흡수 중에는 최초 생성과 재사용을 구분한다. 같은 틱에 파괴된 물체에서 생긴 입자가 풀 슬롯 순서에 따라 먼저 이동하지 않는지 확인한다. |
| 스프라이트·텍스처 | 집행관은 여섯 자세에 PNG 한 장을 공유한다. Point 필터, 무압축과 최대 크기는 렌즈·장갑 경계를 보며 확인한다. 배경과 반투명 발광은 정렬과 필터가 달라 섣불리 같은 아틀라스로 묶지 않는다. |
| GPU 중복 | 반격 광선의 피해 선분은 Hazards가, 화면의 본체·광원은 Visuals가 맡는다. Frame Debugger에서 같은 광선을 두 벌 그리지 않는지 확인한다. 낙하점 예고 원은 24개 단위 방향을 공유하고 한 번의 SetPositions로 갱신한다. |
| 2D 조명·VFX | 본편은 SpriteRenderer/LineRenderer와 가산 효과를 쓴다. URP 비교 씬에서는 동일 장소에서 Light2D 수, 그림자, Normal Map, Bloom을 하나씩 켜고 GPU 시간과 선명도를 기록한다. |
| 물리·타일 | 본편과 연습 씬을 나눠 살핀다. Physics2D 모듈의 접촉·캐스트·스텝 수를 보고 연속 타일 지형에서는 TilemapCollider2D + CompositeCollider2D의 합성 경계와 정점 수를 점검한다. 카메라가 흔들리면 보간된 Transform을 LateUpdate에서 샘플링하는지 먼저 본다. |
| 이동·컷신 | FPS 30/60/120에서 입장, 회피, 중간 스킵, 자연 종료와 첫 입력을 각각 녹화한다. 다이나믹 몸체는 FixedUpdate가, 컷신 중 키네마틱 몸체는 연출 코드 한 곳이 소유한다. Cinemachine 설치 시 따라가는 대상의 갱신 시점과 Brain의 Update/Blend 방식을 일치시킨다. |

## 코드와 저장 경계

현재 `Assets/Scripts`에 본편과 연습 컨트롤러가 함께 있고 `Assets/Editor`는 편집기 어셈블리로 분리되어 있다. `Main` 부트스트랩에서 실제 본편을 생성하므로 새 Boot 씬이나 asmdef를 즉시 끼우면 씬 자동 초기화 및 타입 참조가 달라질 수 있다. 분리를 진행할 때는 다음 순서가 안전하다.

1. Unity 참조가 없는 Rules를 폴더와 단일 asmdef로 먼저 옮기고 기존 .NET 검사를 실행한다. Runtime이 Rules를 참조하게 하고 Editor 검사는 Runtime만 참조한다.
2. 다음으로 전투 서비스와 프레젠테이션을 분리한다. 피해 확정·페이즈 종료·퇴장을 단일 소유자가 발행하고 시각 및 음향이 구독한다. ScriptableObject는 공유 설정에 사용한다. 현재 체력과 쿨타임은 전투 인스턴스에 보관하고 재시도 때 초기화한다.
3. Boot는 입력 프로필과 저장 초기화, 스테이지는 지형·체크포인트, 보스는 임시 적·투사체·컷신 소유권을 가진다. 씬 분리 전후에 승리 직전 세이브, 대화 중 종료, 승리 직후 이어하기, 이전 버전 세이브를 비교한다. 행정구 클리어는 한 번만 기록되어야 한다.
4. 출시 후보는 개발 QA 프로필과 분리한다. Build Profile의 씬 순서, 입력 패키지 잠금, 셰이더 포함, 한국어 폰트, 키 변경·그래픽 설정 저장, 포커스 상실 후 입력을 확인한다. Development/Script Debugging을 끈 빌드에서도 텍스처·음원·에셋 로딩을 확인한다. 스트리핑 수준을 올릴 때는 저장 복원과 런타임 생성 컴포넌트를 다시 시험한다.
