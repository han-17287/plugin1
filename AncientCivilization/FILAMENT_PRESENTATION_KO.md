# 백 경위의 장비와 전투 화면

## G0 · 출발점과 판독 목표

이번 변경의 기준은 본편 Main과 그 안에서 연결되는 5개 층 탐험로다. 현재 프로젝트는 기본 렌더 파이프라인, SpriteRenderer, LineRenderer, IMGUI를 사용한다. 패키지 목록에는 URP가 없고 2D Renderer용 그래프는 OptionalURP에 있다. 기존 캐릭터의 자세, 적 실루엣, 플랫폼 타일, 입력 타이밍을 유지하면서 발광의 의미와 화면 안의 우선순위를 정리했다.

기존 빔은 코어와 외광이 모두 차가운 계열이고 수집 입자도 파랬다. 콘센트와 소환 블레이드를 같이 놓으면 진행 방향, 탄약, 무기를 색만으로 구별하기 어려웠다. 본편에는 화면 후처리가 있었고 순찰 카메라에는 없었다. 같은 장비가 방을 건너며 다르게 보이는 원인이었다. 이번 요청에는 비교용 게임 캡처가 들어 있지 않아 광량과 프레임 시간에 대한 결과 점수는 보류한다.

| 실기 채점 항목 | 1점 | 3점 | 5점 |
| --- | --- | --- | --- |
| 명암과 팔레트 | 밝은 배경에 장비가 묻힘 | 일반 방에서 구별 | 흑백, 밝은 창문, 불 끈 방에서도 바닥·플러그·마커를 찾음 |
| 실루엣·픽셀·광원 | 핀과 손잡이가 한 덩어리 | 기본 배율에서 분리 | 절반 배율에서도 핀 두 개와 칼끝이 따로 보이고 하이라이트 방향이 일치 |
| 배경 깊이와 화면 구성 | 위험이 장식과 겹침 | 정지 화면은 읽힘 | 전속 이동에서도 다음 발판·소켓·적 예고가 차례로 보임 |
| 이펙트와 지속 | 잔광이 다음 공격을 덮음 | 1대1 전투는 읽힘 | 3단 레이저와 보스 공격이 겹쳐도 사선과 안전 지대를 읽음 |
| UI·피드백 | 현재 장착 여부를 틀림 | HUD를 보고 맞힘 | 소리와 허리 표시만으로도 준비·장착·재충전을 구분 |

2점과 4점은 양옆의 조건 사이로 기록한다. 이동·전투·보스·대화 각 한 장면에서 4점 이상이 목표다. 오늘은 손잡이 식별과 빔 읽기, 이번 주는 같은 카메라에서 5개 층 조명 및 낮은 품질 촬영, 이번 달은 최저 사양 PC와 WebGL에서 보스 연속전 GPU 측정 및 배경 반복 문양 수정 순서로 잡는다.

## G1 · 빛을 놓는 위치

| 신호 | 색과 형태 | 사용할 곳 |
| --- | --- | --- |
| 이동 | 하늘색 #5CCBFF, 두 핀·흐르는 선·호 | 전선, 콘센트, 견인, 스윙. 밝은 바탕에 먹빛 피복을 남긴다 |
| 충전 자원 | 달걀노랑 #FFC73B, 작은 마름모 | 일반 수집 입자와 허리 배터리의 1~3개 점등창 |
| 소환·근접 | 앰버 #FF9F32, 아래 화살표·검은 칼등·유리 전구 | 착지 예고, 블레이드, 칼 궤도 |
| 레이저 | 주황 → 상아색 → 금빛 백색, 연속된 폭 | 중앙이 가장 밝고 발사구·실제 벽 착탄점에 광원이 맺힌다 |
| 위험 | 연지/적주황, 보라 전기, 빗금·펄럭이는 경고선 | 적 예고와 피해. 집행관 고유의 푸른 직사각 입자는 개별 사선과 예고 형태로 구분 |
| 확장 팔레트 | 희귀 초록 마름모 속 흰 점, 위험 적주황 가시형 | 해당 자원 판정이 있는 방에서 사용 |

본편·탐험로 카메라에는 AncientCameraFX가 붙는다. Inspector 시작값은 HDR 허용, Bloom Threshold 0.82, Strength 0.32, 반경 2.8화소다. 색상 최대 채널에서 광량을 구한 뒤 원래 색을 유지하며 가까운 네 방향과 먼 네 방향을 번지게 한다. 꽂힌 점 주변은 95ms 동안 최대 0.28을 더한다. F6은 바깥 발광과 고비용 장식을 줄이고 F5는 흔들림·섬광을 줄인다. 약한 기기에서도 무기 본체, 위험 전조, 소켓과 장착 문구가 남는다.

URP로 전환할 때는 본편을 복제한 검증 브랜치에서 2D Renderer, 카메라 HDR와 Post Processing, Volume Layer Mask, Global Volume 활성화, Bloom 오버라이드의 체크박스, HDR 소재의 발광 폭을 차례로 확인한다. Sprite Lit Graph는 알베도와 마스크를 개별 샘플링하고 마스크에 HDR 색×세기를 곱해 더한다. 광원 계산과 다른 패스에서 발광을 더해 암부에서도 형태가 남게 한다. 오브젝트들은 재질을 공유하고 씬별 전역값과 개별 점등값을 분리한다. 실제 SRP Batcher 동작은 Frame Debugger로 확인한다.

아래는 URP 이전 시의 **튜닝 시작값**이다. 현재 빌드에서 활성화된 컴포넌트 수치와 구분한다.

| Light2D | 색 | 강도 / 외부 반경 / falloff |
| --- | --- | --- |
| 배경 전체 | 회청 | Global 0.30, 반경 없음 |
| 주인공 | 따뜻한 흰색 | 0.22 / 2.2 / 0.70 |
| 플러그 · 활성 소켓 | 하늘색 | 0.70 / 1.4 / 0.80, 소켓 0.40 / 0.9 / 0.75 |
| 전구 · 보스 약점 | 앰버, 약점 상아색 | 0.85 / 1.5 / 0.80, 0.70 / 2.1 / 0.75 |

URP Volume은 Bloom threshold 1.0, intensity 0.28, scatter 0.55, vignette 0.10부터 시작한다. 색수차·필름 그레인은 0, 채도 -4, 노출 0, 바닥 그림자만 약한 남색을 기준으로 삼는다. 신호 주변 한두 픽셀이 붙으면 먼저 반경을 줄이고, 밝은 하늘이 번지면 문턱을 올린다. 광원이 사라지면 Game 뷰에서 활성 카메라와 발광 마스크 알파부터 확인한다. 실제 Shader Graph와 URP 소켓 플래시 컴포넌트의 적용 순서는 [옵션 가이드](OptionalURP/BLUE_PLUG_V5_KO.md)에 있다.

## G2 · 이펙트와 판정의 박자

보이는 위험 신호, 피해 판정의 단단한 중심, 충돌 지점, 남는 장식 순서로 예산을 준다. 처음 1~3프레임에 짧은 점등을 놓고, 타격 방향으로 불티를 보내고, 잔광은 다음 예고 전에 걷어낸다. 아래 수치는 60Hz 기준 작업 기준이며 모션 재생 속도와 별개로 판정은 게임 시간으로 처리한다.

| 사건 | 중심 형태와 여운 | 큐와 확인점 |
| --- | --- | --- |
| 돌리기·던지기 | 타원 회전의 앞/뒤 정렬, 오른손 릴리즈, 왼손에서 풀리는 피복, 끝광 | 돌리는 속도에 풍절음 피치가 따라오고 놓자마자 궤도가 펴진다 |
| 꽂힘·빗나감·이동 | 핀을 맞춘 점광과 좁은 링, 견인 때 진행 방향 잔상, 실패 때 회수 | 딸깍은 도킹 순간. 일반 콘센트에 꽂힌 직후에는 몸 잔상이 생기지 않아야 한다 |
| 스핀·전이·도착 충격 | 손 가까운 궤도, 적을 잇는 짧은 아크, 도착 위치의 확장 링 | 같은 스핀에 매 프레임 피격 섬광이 겹치지 않게 실제 타격 이벤트에 묶는다 |
| 소환·낙하·설치 | 바닥 황색 경계, 카운트다운, 날의 수직 꼬리, 지면 링, 손잡이의 두 구멍 | 예고 1.2~2초. 착지 섬광은 충돌 시점에 한 번. 전기장의 바깥선은 평시에도 남긴다 |
| 샤프심 전구 블레이드 베기 | 세로·가로·사선의 실제 칼끝 좌표를 활성 구간 동안 이어 그린다. 접촉 불티 3개는 140ms 동안 사라진다. | 헛베기는 풍절음, 벽은 금속음, 적 명중은 접촉음으로 구별한다. |
| 충전 레이저 | 백열 코어, 내부 프로파일, 외곽 오라, 발사구, 착탄광 | 중앙과 외곽 폭을 구분한다. 빔이 벽을 맞으면 광원도 같은 좌표에서 멈춘다 |
| 과부하·파손 | 중심에서 확장하는 200ms 링, 전지 점멸과 꺼진 손잡이 | 해제된 뒤 재생 시간만 표시하고 유효하지 않은 공격 프롬프트를 지운다 |
| 입자·전기·유리 | 마름모 중심, 외광, 짧은 파편 | 수집 중 외광을 키운다. 공격 예고와 위험 경계는 장식 위에 남긴다 |

시각층은 SpriteRenderer, 공유 재질, 반복되는 LineRenderer 풀로 구성한다. 파편은 짧은 피크에서만 늘린다. 새 VFX Graph를 시험할 경우 URP 자산과 2D Renderer에서 빌드한 WebGL/PC에 실제 출력되는지부터 본다. 비교 대안은 재사용 2D 선과 4~8프레임 스프라이트 시트다. 기존 화면 흔들림과 히트 강조는 FieldFeedback 프로파일에 둔다. 일반 스핀은 흔들림 0, 약한 타격 1회, 과부하는 센 타격 1회로 조정하고 각 연타가 확대를 연장하지 않는지 확인한다. 연출 재조정의 예상 작업량은 도킹·반동 각각 1~2시간, 베기 3단과 연속 빔 각각 반나절, 보스 간 충돌 검토 하루다.

## G3 · 축소해도 남는 원화

이번 방향은 선명한 도트 원화에 따로 구운 발광 마스크를 겹치는 방식이다. 기하형 네온은 방 하나를 빠르게 그릴 수 있지만 핀과 칼날의 재질 구분에 약하다. 고해상도 핸드페인트와 리깅은 유리 반사를 세밀하게 그릴 수 있지만 기존 캐릭터 한 걸음의 픽셀 밀도와 관절을 전부 다시 맞춰야 한다. 분리형 도트와 국소광은 처음 한 장비에 반나절~하루, 같은 규칙을 적용하는 변형은 수시간이 시작점이다.

열 가지 작화 기준을 공유한다.

1. 플레이 가능한 장비는 회전한 실루엣만으로 종류를 구별한다.
2. 밝은 환경 위에 핀 사이 공간과 어두운 피복 한 줄을 남긴다.
3. 손잡이 중앙과 칼끝을 고정 피벗으로 삼아 자세마다 떨리지 않게 한다.
4. 날 몸체는 어두운 강철, 중간 금속색, 밝은 모서리, 국소 하이라이트 네 단계로 조각한다.
5. 좌상단 조명을 공통으로 두고 실제 전구에서 새는 빛만 반대면에 더한다.
6. 투명한 유리 몸체는 프레임과 내부 필라멘트를 분리한다.
7. 이동은 하늘색과 원호, 위험은 적색·보라와 방향성 표시를 함께 쓴다.
8. 배경은 원경·구조물·플레이 지면·짧은 전경으로 나누고 화면 속도 비율 0.12/0.35/1/1.08부터 시험한다.
9. 벽돌 반복 세 장마다 깨짐·배관·먼지 변형을 주되 콘센트 주변은 핀 한 개 너비만큼 비운다.
10. 얼굴·소매·코어의 작은 움직임을 같은 프레임에 몰지 않고 적 예비동작이 먼저 읽히게 한다.

새 FilamentBladeAtlas는 좌측 원화와 우측 마스크가 각각 36×96px, 40 PPU, Point 필터, 밉맵·압축 끔이다. 칼끝 아래 중앙이 피벗이며 게임에서 0.72배로 보이는 장비다. 캐릭터의 실제 화면 키를 우선해 배경 타일, 거대 보스의 갑주, UI 아이콘 픽셀 크기를 맞춘다. 생산층 녹슨 적갈, 생활층 차콜·낡은 황토, 관리층 자주·청회, 거주층 회녹, 최상층 먹색·상아를 바탕색으로 두는 것이 시작 팔레트다. 적은 방향과 위협, 보스는 약점과 공격 예고, 주인공은 왼손과 오른손의 줄 접점을 확인한다. 에셋 외주·라이브러리는 상업 이용, 재배포 및 원본 배포, 변경·표기 조건을 기록한다. 생성 이미지는 기존 작품의 고유 장비나 실루엣을 재현하지 않고 프로젝트 원화로 피벗과 픽셀을 다시 맞춘다.

## G4 · 장착 계기판

본편은 좌상단에 체력·세 칸 축적·자원을, 우상단에 목표와 장착 상태를 둔다. 탐험로는 방 이름 바로 밑에 같은 계기판을 쓴다. HUD의 두 핀은 조작 상태를 나타내고, 몸의 허리 전지에는 실제 축적량에 따라 세 창이 차례로 켜진다. 색 외에도 켜진 개수, 소켓 구멍, 손잡이의 재생 시간을 읽을 수 있다.

```text
1920 × 1080의 본편 예시
┌─ 체력·전지·입자 (24,24) ──┐                  ┌─ 현재 목표 (1470,24) ─┐
│ 세 칸 축적 / 실제 보유량     │                  │ 장착 상태와 가능한 키    │
└───────────────────────┘                  └──────────────────┘
                             캐릭터 옆 대화
                           보스 HP / 페이즈
```

기존 IMGUI의 기준 해상도는 본편 1280×720, 탐험로 1060×640이다. 긴 문구는 여러 줄로 표시하며 상태·시간이 바뀔 때만 텍스트를 갱신한다. 장착 뒤에는 베기·레이저·분리·과부하가 표시된다. 미장착에서는 소환 비용과 연결 조작이 표시되고 바닥 마커와 손잡이 포트가 낙하부터 장착까지 안내한다. 메뉴·무전 자막·재시작 확인은 같은 한글 글꼴과 얇은 외곽 패널을 쓴다.

Canvas로 옮길 때는 Screen Space Overlay, Canvas Scaler 1920×1080, Match 0.5, 네 모서리 앵커와 Safe Area, 9-slice 음영 패널을 시작점으로 삼는다. TMP 한글 폰트는 배포 권한과 폴백 자모를 검증한다. Overlay는 카메라 Bloom 이후 그려지므로 UI 하이라이트는 분리된 글로우 스프라이트를 쓴다. HUD 연출 튜닝 시 게이지 증가 100ms, 단계 강조 120ms, 타격 후 체력 잔상 180ms, 재사용 가능 신호 100ms를 상한으로 잡고 조준점 위에는 올리지 않는다.

## G5 · 실제 화면 점검

Unity 메뉴의 **PLUGIN → 검증 → 블레이드 픽셀과 발광**은 임포트·피벗·발광 마스크의 셀 위치를 검사하고, 테스트 텍스처를 GPU로 그려 주황색 가장자리의 광량 증가 및 범위를 읽는다. 이 검사는 GPU가 있는 환경에서 실행한다.

플레이어 위치·카메라·입자량·공격 시점을 고정한다. Game 뷰 1920×1080에서 F5/F6 조합, 1280×720, 16:10, 21:9를 같은 자세로 캡처한다. 이동/착지/레이저/보스 대화에서 F6을 바꿔 핀과 예고 마커의 코어는 살아 있고 바깥 오라만 줄어드는지 본다. 흑백으로 바꾼 뒤 절반으로 축소해도 모양과 위치를 읽을 수 있어야 한다. 비용 비교는 Profiler CPU/GPU 타임라인, Frame Debugger의 투명 겹침과 빔 패스, Memory Profiler의 방 전환 30회 후 텍스처 수를 기록한다. 목표 60fps에서 프레임 예산은 16.67ms이며 실제 최저 사양 측정값은 별도다.

1. 처음 본 방에서 하늘색으로 보이는 다음 목적지를 찾았나?
2. 밝은 벽 앞에서도 두 금속 핀과 소켓 간격이 읽히나?
3. 소환 직후 칼이 떨어질 위치와 대기 시간을 가리킬 수 있나?
4. 낙하 중인 손잡이와 바닥에 꽂힌 손잡이에 같은 입력을 자연스럽게 썼나?
5. 장착하고 좌클릭이 바뀐 시점을 알아챘나?
6. 검은 칼등과 노란 궤도만 보고 세로·가로·사선 베기를 구분하나?
7. 레이저 중심과 빛만 닿는 범위, 벽에 맞은 위치를 구분하나?
8. 허리의 전지 창을 보고 HUD 없이 대략적인 축적 단계를 맞히나?
9. 과부하 직후 다시 소환할 수 있는 시점을 이해하나?
10. 낮은 품질과 작은 화면에서도 보스의 다음 공격을 같은 속도로 읽나?

맞히기 어려운 신호는 배경 → 신호 테두리 → 발광 반경 순서로 고친다. GPU 병목은 외곽광과 파편 수부터, 입력 지연은 실제 입력 이벤트와 표시된 첫 프레임 사이를 먼저 측정한다. 현재 플레이 캡처와 GPU 프레임 측정은 Unity Editor에서 확인할 항목이다.
