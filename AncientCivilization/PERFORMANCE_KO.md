# v0.25.0 하층 확장과 측정 범위

생산구·생활부가 각각 10,400단위로 늘어나 정적 배경 메시를 128단위 묶음으로 나눴습니다. Unity가 긴 수사 이정표 안에서도 화면 밖 메시를 제외할 수 있게 하며, 넓은 바닥·천장 사각형의 실제 범위는 보존합니다. 층·인접 이정표의 표시 규칙도 유지합니다.

새 주민 48명은 같은 이름마다 한 인물을 재사용하고, 장치 72곳은 미리 생성해 카메라 주변에서 표시합니다. 현장 경비는 한 번에 두 명을 만들며, 생활부 탐조등 증원과 가까운 경비 수를 함께 셉니다. 생활부 배경 8종과 현장 장치 4종의 픽셀 텍스처는 최초 생성 후 공유합니다. 이 수량은 구현 구조이며 실측 draw call·메모리·프레임 수치는 아닙니다.

실기에서는 새 게임 로딩, 10,400단위 수사로 왕복, 주민 재배치, 감시 구역, 대형 물체 투척, 보스 흡입·미사일 난사를 같은 F6/F8 설정으로 측정해야 합니다. Unity Editor가 없는 현재 환경에서는 FPS 향상이나 목표 프레임 유지를 판정하지 않았습니다.

v0.20.0 변경: 전체 와이어 지점별 halo 오브젝트 생성을 고정64개 표시 풀로 바꿨습니다. 같은 층의 화면 주변 후보에서 가까운 지점을 고정 배열 heap으로 골라 표시하고, 움직이는 고리의 현재 좌표를 읽습니다. 선택은 약0.1초·카메라 이동·줌·층/후보 변경 때 갱신하며 프레임마다 전체 목록 정렬이나 임시 배열을 만들지 않습니다. 이는 오브젝트 수와 관리 구조의 변경이며 실제 FPS 개선 수치는 아닙니다. F6 저품질/메인 화면에서는 표시를 숨기고 물리 고리와 와이어 조작은 유지합니다. 실제 Unity Profiler의 Renderer 수·GC·프레임 비용은 별도 확인해야 합니다.

v0.19.0 생산구에서는362단위 튜토리얼과 별도1,600단위 수송 터널,12개 재사용 잔재/폭탄, 기존64개 투척물 풀을 사용합니다. 추격/갑판 구간은 F9/F10에 표본을 남기며 자체 컷신은 일시정지 상태이므로 통계에서 제외합니다. 컷신 프레임·GC·렌더링은 Unity Profiler로 별도 측정해야 합니다. 실제 FPS 개선률은 미측정입니다.

# v0.21 변경과 측정 대기

명중 표시는 기존 피해 숫자 배열에 실제 접촉 위치를 저장하고 기본 흰 텍스처로 그립니다. 베기마다 허공에 만들던 접촉 파편은 제거했습니다. 커서 충전 안내는 표시 비율·입자 유무·글자 크기가 바뀔 때 문구와 측정 폭을 갱신합니다. 빠른 이동 방향을 따르는 카메라와 공중 확대는 화면 계산이며 이동 속도나 충돌 규칙을 바꾸지 않습니다. 이 변경으로 얻은 실제 FPS·GC 개선량은 측정하지 않았습니다.

하층 작업장의 배선·작업등·수신기는 미리 만들고 저장된 목표 상태와 카메라 범위에 따라 표시합니다. 전력 복구 빛은 같은 표시물을 재사용하며, 재접속으로 이미 완료한 상태를 복원할 때 다시 시작하지 않습니다. 추격의 실제 회피 안내·피격 도움말·재승선 고리 점멸도 기존 표시와 위험물 풀을 사용합니다. 작업장 복구 전후·빠른 공중 이동·충전 안내·연속 추격을 같은 해상도와 F6/F8 설정에서 F9/F10 및 Unity Profiler로 비교해야 합니다. 실제 렌더러 수·드로콜·GC·프레임 시간과 화면 가독성은 실기 확인 대기입니다.

# 실제 프레임 측정

v0.17.0은 다섯 층의 연속 챕터와 굵은 레이저를 사용합니다. 기존 정적 배경 묶기·풀 재사용·와이어 계산/전달 최적화·HUD 문자열 캐시는 유지합니다. **이 개발 환경에는 실행 가능한 Unity Editor가 없어 실제 게임 FPS 개선률은 측정하지 않았습니다.**

## 게임 안에서

- F6: 고품질 / 가벼운 효과. 충돌·피해·적 공격 규칙은 바뀌지 않습니다.
- F8: 목표 60 → 120 → 144 → 240 → 무제한. 기본 목표 240. 수직 동기화는 끄며 목표 설정을 저장합니다. 모니터 주사율과 기기 처리량은 별개입니다.
- F9: 최근 최대 240개의 실제 플레이 프레임 평균·P95·최대 시간과 최근 프레임 GC 할당량, 정적 장식/묶음 수, 투척물 풀 사용을 표시합니다.
- F10: F9 표시 중 최근 프레임을 CSV로 저장합니다. 저장 경로는 게임 메시지에 표시하며 `Application.persistentDataPath` 아래입니다. 외부 전송은 없습니다.

메인 화면·일시정지(대화·승강기·종료 연출 포함)·포커스가 없는 동안은 프레임 표본을 추가하지 않습니다. 이정표 완료의 이동 중 무전은 일시정지가 아니므로 정상 플레이 표본에 포함합니다. 실제 플레이 중 1초 이상 멈춘 프레임은 지표에서 숨기지 않고 포함합니다. 통계는 짧은 이동 창이므로 전체 플레이의 평균이나 최저 FPS를 뜻하지 않습니다. P95가 8.33ms면 최근 표본의 약 95%가 그 이하이며, 120FPS에 필요한 시간 예산이 8.33ms입니다. 60/144/240FPS의 예산은 각각 약 16.67/6.94/4.17ms입니다.

GC 값은 Unity ProfilerRecorder가 제공하는 가장 최근 표본이며 창 전체의 평균이 아닙니다. 플랫폼이 카운터를 제공하지 않으면 미지원으로 나옵니다. 풀 누락 수는 이미 살아 있는 투척물을 옮겨 재활용하는 대신 새 생성 요청을 거절한 횟수입니다. 정상 플레이에서 계속 증가한다면 투척 밀도와 수명을 확인해야 합니다.

CSV 열은 `sample,frame_ms,floor,target_fps,enhanced,finale_phase,campaign_room,sniper_phase,sniper_objects,hero_x,hero_y,horizontal_speed,capture_energy,attack_mode,wired,laser_active,production_phase,production_round,production_mounts,story_stage`입니다. 각 표본이 발생한 시점의 층·설정·추격 단계를 기록합니다. `campaign_room`은 현재 진행 중인 수사 이정표 ID(0~19)이며 -1은 활성 이정표가 없는 상태입니다. 연속 맵의 실제 카메라 위치나 지나간 물리 구간 번호를 뜻하지 않으므로 v0.17.0부터 같은 표본의 `hero_x`/`hero_y`로 실제 위치를 함께 기록합니다. `horizontal_speed`는 부호 있는 가로 속도, `capture_energy`는 저장 입자량, `attack_mode`/`wired`/`laser_active`는 각각 공격 모드/와이어 연결/레이저 발사 중이면1입니다. 따라서 같은 이정표 안에서 이동 중인지, 빔 발사 중인지 구분할 수 있습니다. 마지막 저장 순간의 설정을 과거 표본 전체에 적용하지 않습니다. 저격수 페이즈(0은 해당 전투 밖)와 수류탄·압축판 활성 수도 표본 시점에 기록합니다. F9의 저격수 전용 풀은24칸이며 기존64칸 풀과 따로 표시합니다. 입력 시각·GPU 프레임 시간·프로파일러 마커는 포함하지 않습니다.

v0.19.0의 네 추가 열은 표본 시점의 생산구 단계(AncientProductionPhase enum의0~9), 추격 회차0/1, 탑승 횟수0~3, 스토리 단계다. 자체 컷신은 통계에서 제외하므로 주로 주행·접근·승선·갑판 표본을 비교한다. 작업장 배경은 기존 정적 레이어 안에 추가하며 실제 드로콜 증가 여부는 Unity에서 확인한다. 위험 범위/신관 표시도 미리 만든 풀을 재사용한다. 피니셔 빔 갱신의 임시 배열을 제거했으며, 음향 파형은 메뉴/부팅 때 한 번 생성한다. 이 변경은 측정된 FPS 향상 수치가 아니다.

## 같은 기기에서 비교

1. 같은 해상도·창 모드·전원 설정으로 기존 버전과 새 버전을 각각 실행합니다. Editor의 Game 뷰보다 같은 조건의 플레이어 빌드 비교를 권장합니다.
2. F8 목표와 F6 품질을 동일하게 맞춥니다. CPU/GPU 처리량의 차이를 보려면 무제한, 실제 사용감을 보려면 같은 주사율에 맞춘 목표를 씁니다.
3. 첫 로딩/시작 직후 구간을 따로 기록하고, 20초 이상 안정된 뒤 같은 장소·같은 조작을 비교합니다.
4. 도입부 걷기, 긴 와이어 연속 연결, 이정표 사이 64단위 통로/이동 무전, 완료 구간 되돌아가기, 굵은 레이저/보스 투척물 파괴·수집, 마지막 트럭 추격에서 각각 기록합니다. 입력·적 상태 차이 때문에 단 한 번의 최고 FPS를 개선률로 쓰지 않습니다.
5. Unity Profiler의 CPU·GPU·Rendering·GC를 함께 봅니다. F9의 평균이 높아도 P95/최대 시간이 나쁘면 순간 끊김을 조사합니다.
6. 같은 보스 재도전 10회 후 적/투척물/임시 전리품 수와 메모리가 누적되는지 확인합니다.

## 개발 중 확인한 수학 비용

동일한 출력 버퍼와 중간값 체크섬을 쓰는 독립 .NET 벤치마크에서, 20,000프레임 × 두 나선 × 192점 계산은 개별 삼각함수 방식 227.36ms, 점화식 111.62ms였고 점화식의 정상 반복 중 관리 메모리 할당은 0바이트였습니다. 최적화 컴파일 옵션을 사용한 측정입니다. .NET 8 SDK가 있으면 `dotnet run --project Tools/WireBenchmark.csproj -c Release`로 같은 작업량을 재현할 수 있습니다. 수치는 기기와 실행 환경에 따라 달라집니다.

이는 **와이어 좌표 계산만** 비교한 한 환경의 수치입니다. Unity의 LineRenderer 전달·렌더링·물리·UI·GPU를 포함하지 않으므로 게임 FPS가 약 2배가 됐다는 뜻이 아닙니다. 프로젝트 전체 무할당이나 240FPS를 보장하는 자료도 아닙니다.

v0.13.1 스윙8포즈와 픽셀 텍스처는 플레이어 초기화 시 캐시합니다. 레이저 외곽은 프레임마다 파티클을 생성하는 대신 작은 광도 텍스처와 선 렌더러를 사용합니다. 실제 FPS 개선/저하 수치는 측정하지 못했습니다.

블레이드 48프레임은 초기화 시 세 장의 시트를 한 번씩 팔레트화합니다. 측정 영역으로 스프라이트를 만든 뒤 시트의 CPU 복사본과 가져온 원본 리소스를 해제하여 런타임 GPU 시트만 캐시합니다. 베기 잔광의 9점 배열과 파란 입자 48개/후광은 재사용하며, 수집 중 새 머티리얼·텍스처·오브젝트를 만들지 않습니다. 이 구조 확인은 실제 메모리나 FPS 측정값이 아닙니다.

층별 배경 다섯 장면은 텍스처 한 장/스프라이트 다섯 개를 공유하고 한 렌더러에서 현재 장면만 표시합니다. 기존 파노라마 렌더러 세 개는 생성하지 않습니다. 카메라를 그리기 전에 위치·화면비를 맞추며, 갱신 중 오브젝트·재질·텍스처를 새로 만들지 않습니다. 프레임 개선률이나 실제 드로콜 감소량은 측정하지 않았습니다.

연속 챕터의 장식·조명·동적 기믹은 활성 이정표 ID 대신 실제 카메라 위치와 인접 구간으로 표시를 판단합니다. 완료한 곳으로 돌아가도 기믹을 유지하고 연결 통로의 빈 배경을 막습니다. 이정표 완료는 맵 재생성·위치 이동 없이 이어지고 배경 패럴랙스도 층의 물리 위치를 사용합니다. 이 구조는 실기 렌더링 비용·드로콜·메모리 측정값이 아닙니다.

일반 레이저는 최대 24단위의 본체·흰 중심·외곽 빛을 재사용 렌더러로 표시합니다. 벽 판정은 본체 폭의 BoxCast와 같은 폭의 목표 판정을 사용합니다. 넓어진 표시와 충돌 조회의 실제 비용은 F9/F10·Unity Profiler로 따로 비교해야 합니다. 메뉴의 9종 배경과 별도 60fps 애니매틱도 실제 게임 FPS를 보장하는 자료가 아닙니다.

v0.17.0은 옥상 기록 표시를 0.01초 단위로 캐시하고 정지한 타이머 문자열을 재사용합니다. 일반 적6종의 알파 분할은 시작 시 미리 수행해 첫 등장 중 처리를 피합니다. 유지 중 레이저는 대상128개의 참조 배열을 재사용하며 같은 발의 중복 피해를 막습니다. 새 CSV 상태 열과 함께 실제 프레임·GC 비용을 비교해야 하며 이 구조 변경을 FPS 개선 수치로 환산하지 않습니다.
